# M0 container workflow

Status: tooling and local ROS smoke checks PASS; local Git authentication and independent review/reproduction remain BLOCKED. This is not a completed M0 gate.

## Acceptance and environment

M0 requires reproducible Ubuntu 24.04/Jazzy tooling, real talker/listener delivery, retained versions/logs, personal branch push, and independent review. Current host is Oracle VirtualBox Ubuntu 22.04.5 x86_64, about 4 GB RAM and 25 GB free disk. Use this host with an Ubuntu 24.04 container. No host upgrade, WSL installation or native Jazzy installation is attempted. Simulator resource requirements remain unmeasured.

The host needs Python 3, Bash, Git, and accessible Docker Engine. Git 2.34.1 and Docker 29.9.2 are now installed with normal-user Docker access; `sudo -n true` still requires a password. A human must install prerequisites using the official Docker Ubuntu guide below and `sudo apt install git`. Do not provide passwords to the agent. Configure Docker access using the official rootless or post-install instructions. The tooling never changes host apt sources, group membership, shell profiles or permissions.

## Commands

Run as your normal user from a Git checkout. This local directory is a connected-GitHub snapshot, not a clone; local private Git authentication is still unverified. Clone the PR branch after authentication is available. Configure your own Git identity and use supported SSH or credential-manager authentication; never embed tokens in URLs.

```bash
bash scripts/doctor.sh
bash scripts/doctor.sh --json
bash scripts/bootstrap.sh --check
bash scripts/bootstrap.sh --install
```

Doctor returns 2 when any prerequisite or the manual write-auth gate is BLOCKED. Bootstrap defaults to check-only, writes no files in check mode, and returns 2 if container prerequisites are missing. `--install` builds the image and runs real ROS smoke checks; failures return nonzero. `--native` always rejects host installation. Arguments are validated; no sudo or password prompts are issued by scripts.

Successful builds use Docker cache on reruns. Each install run creates a fresh ignored `evidence/runs/<UTC>-<random>/` with metadata and transcript. Transcript includes image identity, Docker version, complete resolved apt versions, Python/rclpy information and actual listener delivery. Metadata records commit, dirty state and Dockerfile hash. Copy selected evidence into an indexed review artifact; do not commit large logs. Interrupted runs require inspection; absence of PASS is not success.

Base image is pinned to its registry digest. Additional apt packages resolve at build time and are recorded, not fully locked; preserving the built image is necessary for exact binary reproduction. A later rebuild may resolve newer packages. Review base digest refreshes in a PR.

Enter the image after a successful build:

```bash
docker run --rm -it --user "$(id -u):$(id -g)" -e HOME=/tmp \
  --mount "type=bind,source=$PWD,target=/workspace" \
  smart-mobility-hub:m0 bash
source /opt/ros/jazzy/setup.bash
```

Run Codex on the host as your normal user. The image supports ROS development as your UID. Future rosdep updates/builds happen inside the container, after M1 declares dependencies. No ports, privileged mode, host network or display mounts are required for this headless M0 check.

For clean reproduction, a teammate starts a fresh clone, records its commit, builds with `docker build --no-cache -f containers/Dockerfile -t smart-mobility-hub:m0 .`, then runs bootstrap install. Compare versions and retain both transcripts. This is still NOT RUN locally. Containers launched by the tools are ephemeral (`--rm`); Ctrl+C stops foreground runs. Remove only this project's image deliberately if desired; do not prune shared Docker data.
